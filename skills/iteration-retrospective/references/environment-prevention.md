When to read: before selecting prevention for an evidenced failure involving repository checks, navigation, instructions, tooling, or information access.

# Environment Prevention

Use these lenses only for patterns supported by attempt evidence. They suggest candidates; the ordered mechanism, cost, uncertainty, and skill-eligibility rules in `report-format.md` remain authoritative. This is analysis, not authorization to change files or access services.

- **Existing safeguards:** inspect declared check commands, hook definitions, and CI wiring before proposing a new check. Prefer repairing a relevant disconnected or ineffective check when evidence supports it. Missing lint or CI alone does not establish a failure.
- **Navigation:** when searches missed a relevant file or dependency, identify a precise pointer to existing documentation or a source-of-truth correction. Avoid broad documentation additions without a demonstrated need.
- **Instruction usefulness:** look for duplicated enforcement, conflicting rules, and instructions with no observable contribution to the evidenced task. Propose removal or clarification only with a concrete consequence; inspection alone does not establish measured model behavior.
- **Tool economy:** connect repeated or expensive calls to the same evidence need. Propose bounded retrieval, reusable tooling, or fewer redundant calls while preserving required verification. Do not guess costs or omit necessary checks for speed.
- **Information access:** identify the specific missing log or read-only evidence source and how it would distinguish competing causes. Availability and authorization are prerequisites; do not invent access or results.

Map proposals to existing mechanisms: navigation/procedure edits use `repository guidance`; source-of-truth changes use `refactor`; automated checks use `deterministic check`; reusable retrieval code uses `shared helper`. Apply existing selection rules rather than treating a lens as an extra mechanism. If availability or costs prevent selection, record the missing evidence under `Retrospective Next Checks` and preserve supported selections for other patterns.
