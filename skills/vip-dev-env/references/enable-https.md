# Enable HTTPS for a VIP Local Development Environment

Risk level
- Level: Medium
- Why: Certificate trust changes affect local system and browser trust decisions.
- Controls: Apply controls from `references/security.md`.

High level
- HTTPS requires trusting the local CA certificate generated by the LDE.
- Some browsers may still distrust the cert even after install (Chrome/Safari).
- Trust only the local LDE CA from your own machine path, not arbitrary certificate files.

Find the CA certificate
- The Lando CA lives in the VIP-CLI Lando certs directory; the exact base path and file extension are platform- and version-dependent, so discover them rather than hard-coding.
- The certs directory is typically under the VIP-CLI data dir, for example `<vip-data-dir>/lando/certs/`, where `<vip-data-dir>` is usually `~/.local/share/vip` (on Windows WSL, access the distro home via `\\wsl.localhost\<DISTRO>\home\<USER>\...`).
- Locate the CA file (named like `vipdev.lndo.site.pem` or `.crt`) by discovering the VIP-CLI data directory first, then searching under it. On Linux/WSL2 it is commonly `~/.local/share/vip`; if unsure, search from `$HOME`:
  - `find "$HOME" -path '*lando/certs/*vipdev.lndo.site*' 2>/dev/null`

Trust the cert
- Use the discovered CA path in the OS trust command. Examples (substitute `<ca-path>`):
  - macOS: `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <ca-path>`
  - Windows (as admin): `certutil -addstore -f "ROOT" <ca-path>`
- Linux note: trust-store commands vary by distro and browser. Prefer official Lando trust instructions for your distro.
- For exact OS steps, use Lando’s cert trust docs and substitute the discovered CA path.

Verification
1) Restart browser after trusting the CA.
2) Open the HTTPS URL from `vip dev-env info --slug=<slug>`.
3) If trust still fails, remove old CA entries and re-import the current LDE CA.
