# complexity-audit

> Identify avoidable complexity and propose the smallest supported simplification.

This read-only skill performs dedicated audits whose primary goal is identifying avoidable complexity in supplied code, diffs, or paths against requirements, callers, and local conventions. Broader production-code quality assessments, including reviews of complexity alongside other quality dimensions, are excluded. Four evidence gates prevent speculative findings and protect necessary behavior, defensive checks, boundaries, and test seams. Proposals are emitted only for candidates passing all four gates; when none qualify, the report contains no simplification proposal. Standalone implementation requests are excluded. For a mixed request that includes a dedicated complexity audit and implementation, it performs only the audit and returns the report. It reports correctness/security risks directly caused by identified complexity or relevant to simplification safety. It does not apply changes or perform comprehensive correctness/security reviews.

The report uses `Complexity scope:`, `Complexity findings:`, `Complexity limitations:`, and `Complexity verdict:`. Verdict precedence is `Blocked`, then `Incomplete`, then `Findings`, then `No findings`; supported findings remain visible in an incomplete review. A completed review with no findings emits `No actionable complexity findings.`. Missing evidence is a coverage limitation, not a code defect. Each finding exposes all four gates: observed code in `Location:`, lack of justification, the consequence supporting severity, and supporting preservation evidence in `Evidence:`, and the simpler alternative with its maintenance benefit in `Minimal change:`. Preservation constraints alone do not establish behavior preservation. Severity uses the highest matching impact of current complexity: substantial maintenance cost or substantial correctness/security risk is `high`; meaningful cognitive/change cost or risk above minor localized impact but below `high` is `medium`; modest localized overhead or minor localized correctness/security risk is `low`. Risks introduced by a proposed simplification affect preservation, not finding severity.
